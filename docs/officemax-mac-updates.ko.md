# 오피스Max Mac 시험판 업데이트

M5 맥북을 포함한 Apple Silicon용 시험판입니다. Windows에서 추가한 기능과 Mac용 PDF 글꼴 수정을 유지합니다.

## 기존 맥북에서 새 버전 받기

1. 오피스Max 설정 → 정보 → 업데이트 채널을 **베타 버전**으로 바꿉니다.
2. 메뉴 막대의 도움말 → 업데이트 확인을 누릅니다.
3. 새 버전 안내에서 다운로드 페이지 열기를 누릅니다.
4. GitHub 릴리스의 `OfficeMax-<버전>-arm64.dmg`를 받습니다.
5. 작업을 저장하고 오피스Max를 종료한 뒤, DMG 안의 앱을 응용 프로그램 폴더로 옮겨 기존 앱을 교체합니다.
6. 응용 프로그램 폴더에서 오피스Max를 다시 실행합니다. 문서와 사용자 설정은 앱과 별도 폴더에 보관되므로 앱만 교체합니다.

이미 같은 버전이면 새 버전 알림은 나오지 않습니다. 첫 연결 버전은 `0.13.5-beta.1`이며 이전 `0.13.4-mac-preview.2`보다 높은 번호입니다.

## 처음 설치할 때

GitHub 저장소 `charleskang/openoffice` → Releases → 해당 Mac 베타 릴리스에서 arm64 DMG를 받습니다. Apple 배포용 인증서로 서명·공증하지 않은 시험판입니다. macOS가 실행을 막으면 시스템 설정 → 개인정보 보호 및 보안에서 해당 앱의 열기를 허용합니다.

## 업데이트 방식

앱은 켜고 약 15초 뒤, 이후 4시간마다 GitHub Releases에서 새 버전을 확인합니다. 사용자가 고른 베타 채널만 시험판을 확인합니다. 문서 내용이나 API 키를 업데이트 확인에 보내지 않습니다.

현재는 새 버전 알림과 다운로드 페이지 연결을 제공합니다. 앱이 스스로 종료 후 교체되는 자동 설치는 Apple Developer ID 서명과 공증을 준비한 뒤 별도로 연결해야 합니다. Windows 설치본은 이번 Mac 전용 릴리스에서 교체하지 않습니다.

## 다음 Mac 버전을 준비할 때

모든 앱 소스를 전체 빌드한 뒤, `beta` 형식의 더 높은 버전으로 DMG·ZIP과 업데이트 안내 파일을 함께 만듭니다. `tools/mac-update-release.mjs`가 각 파일의 이름·크기·SHA-512, Mac 실행 검사 결과를 검증하고 SHA-256 목록을 생성합니다. 게시 전에는 GitHub 릴리스 초안에 올려 검토합니다.

현재 `OfficeMax Mac beta updates` 워크플로의 출력 재사용은 `aed22bd2`와 앱 소스가 같은 경우에만 허용됩니다. 앱 기능을 수정했다면 전체 Mac 빌드를 사용해야 합니다. 최초 시험판의 Actions 파일이 만료되면 전체 빌드가 필요합니다.
