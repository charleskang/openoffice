# 오피스Max 설치와 업데이트

현재 사용자의 기본 작업 방식은 이 PC에 설치된 앱을 직접 갱신하는 것이다. 별도 설치 파일 생성과 공개 배포는 사용자가 요청할 때만 진행한다. 앱을 정상 종료하고 변경할 앱 파일을 백업한 뒤 적용하며, 문서와 사용자 설정은 교체하지 않는다. 아래 설치 파일 생성 절차는 별도 배포가 필요할 때 사용한다.

개발 실행과 일상용 설치본을 따로 사용한다. 일상용은 시작 메뉴의 **OfficeMax**, 개발용은 `Start-Office-Dev.cmd`로 연다. 설치본의 설정은 `%APPDATA%/OfficeMax`, 개발 설정은 `%APPDATA%/OfficeMax-Dev`에 있다. 기존 이음오피스와도 별개다.

## Windows에서 다음 설치 파일 만들기

이 PC에서 Node.js, Rust, Visual Studio C++와 Windows SDK를 설치하고 `npm ci`를 마친 상태에서 저장소 폴더에서 실행한다.

```powershell
npm.cmd run release:windows -- 0.13.4
```

새 버전은 현재 설치본보다 높은 번호를 사용한다. 명령은 앱 버전과 잠금 파일을 함께 갱신하고 전체 편집기, CLI, 네이티브 도구를 빌드한다. Tectonic LaTeX 엔진을 준비하고 NSIS 설치 파일과 업데이트 정보를 만든다. 로컬 빌드는 서명하지 않으며 GitHub에 올리지 않는다.

결과는 저장소 옆 `outputs/releases/0.13.4/`에 생긴다.

- `OfficeMax-Setup-0.13.4.exe`: 첫 설치와 기존 설치 위 덮어쓰기에 사용한다.
- `latest.yml`: 앱이 새 버전과 다운로드 파일, 검증 해시를 읽는 정보다.
- `OfficeMax-Setup-0.13.4.exe.blockmap`: 같은 빌드에서 생성한 보조 정보다.
- `SHA256SUMS.txt`: 설치 파일의 SHA-256이다.

세 개의 배포 파일은 반드시 같은 빌드의 것을 함께 사용한다. 이미 공개한 버전의 설치 파일을 다른 내용으로 바꾸지 말고 새 번호로 빌드한다. `--reuse-build`는 소스가 같은 업데이트 예행에만 쓰며 실제 기능 변경 뒤에는 사용하지 않는다.

## 설치된 앱에 업데이트 배포하기

현재 설치본은 `charleskang/openoffice`의 GitHub Releases를 확인한다. 코드만 수정하거나 GitHub에 push하는 것으로 설치본이 바뀌지는 않는다.

1. 변경 사항을 검사하고 사용자 저장소에 커밋한다.
2. 높은 버전으로 설치 파일을 만든다. 배포용은 기존 **Windows build** GitHub Actions를 쓰면 빌드 출처도 남길 수 있다. LaTeX 엔진 포함 여부도 이 작업에서 확인한다.
3. GitHub Release에 같은 버전의 설치 파일, `latest.yml`, `.blockmap`과 사용자가 읽을 변경 설명을 올린다. 태그는 `v0.13.4`처럼 앱 버전과 맞춘다.
4. 정식 릴리스를 게시하면 설치된 Windows 앱이 새 버전을 감지한다. 기본 확인은 실행 약 15초 뒤와 이후 약 4시간마다 이루어진다.
5. 앱에서 **지금 업데이트 → 다시 시작 및 설치**를 누르면 새 버전으로 바뀐다. 문서는 작업 전에 저장한다.

GitHub 공개 릴리스는 최종 배포 승인 뒤에 게시한다. 처음 배포할 때는 파일과 설명을 모두 갖춘 초안에서 검토한다. `Windows build`의 `release_tag` 입력은 기존 릴리스에 파일을 붙이는 동작이므로, 파일 없는 정식 릴리스를 먼저 노출하지 않도록 초안 준비와 게시 순서를 확인한다.

GitHub에 게시하기 전에도 새 설치 파일을 직접 실행해 기존 OfficeMax 위에 설치할 수 있다. 이 방법도 같은 앱 식별자를 쓰므로 별도의 제거 과정은 필요 없다. 사용자 문서와 설정은 설치 디렉터리 밖에 유지한다.

## 업데이트 검증과 플랫폼 범위

로컬 예행은 실제 Windows 설치본의 업데이트 주소만 임시로 이 PC의 서버로 바꾸어 다운로드, 파일 무결성 확인, 재시작, NSIS 교체를 시험한다. 새 설치 파일에는 원래 GitHub 주소가 들어 있어 업데이트 후 복구된다. 예행용 문서·가짜 API 키는 별도 임시 프로필에서만 사용한다. 실제 OpenAI 요청은 보내지 않는다.

`tools/rehearse-windows-update.mjs`는 이 PC의 `outputs` 설치 파일과 LaTeX 예제에 의존하는 로컬 검증 도구다. 기존 설치본을 덮어쓰지 않도록 기본적으로 중단한다. `--use-existing-test-install`은 이 도구가 방금 만든 시험 설치를 재개할 때만 사용한다.

Windows 설치 파일은 현재 서명되지 않았다. 배포 대상을 넓히려면 코드 서명과 Windows 신뢰도를 별도로 준비한다. 나중에 서명 주체를 바꾸면 기존 설치본의 업데이트 허용 여부도 다시 검증한다.

Mac의 Apple Silicon·Intel 빌드 설정과 LaTeX 엔진 포함은 유지한다. 현재 Mac 업데이트는 새 버전 알림에서 다운로드 페이지를 열어 설치하는 방식이다. 이 Windows PC에서는 Mac 설치·실행이나 자동 교체를 검증하지 않았다.
